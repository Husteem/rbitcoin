Added

- **`--network testnet5`** (BIP 95). Genesis mined at mainnet height
  975,744, minimum difficulty `0x1a0fffff`, no 20-minute
  minimum-difficulty rule, message start `FIVE`, P2P port 18353, RPC port
  18352, `tb` addresses. Conf takes `testnet5` or `testnet5=1`; NixOS
  `services.rbitcoin.network = "testnet5"`. There are no seeds yet, so name
  a peer with `--connect`.
- **BIP 54 (consensus cleanup) on testnet5 from block 1.** Timewarp and
  negative-interval headers, 64-byte transactions, a coinbase not
  timelocked to the previous height, and more than 2,500 legacy sigops in
  one transaction's inputs are invalid. The mempool refuses the same, and
  `getblocktemplate` (which lists `!consensuscleanup` and requires the
  client to name it) and SV2 `NewTemplate` hand out a conforming coinbase.
  Official BIP 54 vectors run in the consensus suite. Other networks are
  unchanged.
- **Version 3 (TRUC) and anchor packages, as in Core.** RPC submit takes
  `nVersion` 1 to 3. A version-3 transaction follows BIP 431: one
  unconfirmed parent and one unconfirmed child, at most 10,000 vB (1,000 vB
  with an unconfirmed parent). A second child that pays enough evicts the
  first under Core's replacement rules instead of failing
  `TRUC-violation`. A 0-fee transaction may carry one 0-value anchor
  output, which its child must spend (`missing-ephemeral-spends`).
  `submitpackage` admits the anchor parent with its fee-paying child, and
  peers relay the pair as 1p1c, so Bark's exit packages reach the network.
- **A v1 P2P listener for local wallet indexers.**
  `--net-permission-bind v1,noban@127.0.0.1:8335` (conf
  `net_permission_bind=`) accepts plain v1 P2P for NBXplorer, bitcoinj and
  similar clients; a BIP324 peer there still gets v2. Every other listener
  and every outbound connection stay v2 only. The bind needs its own port
  and a private address (loopback intended), is never advertised, and
  stays up under `--listen=0`. `getpeerinfo.transport_protocol_type` is per
  peer.
- **`--rpc-client-version N`** (conf `rpc_client_version=`, NixOS
  `rpc.clientVersion`) sets `getnetworkinfo.version`. The default stays
  190000. Bark's captaind needs 310000.
- **`--discover-from-peers`**, off by default: with no clearnet
  `--external-ip`, announce the IP outbound clearnet peers say they
  reached us at, as Core's `-discover` does behind NAT. Never over Tor,
  I2P, CJDNS, or `--proxy`.
- **Regtest can retarget like mainnet.** `--regtest-block-time` and
  `--regtest-retarget-interval` (e.g. `10` and `60`) run mainnet's
  difficulty adjustment with Core's clamp, so a dev stack can exercise a
  difficulty change on a CPU. Validation, `generate*`,
  `getblocktemplate`, and SV2 all follow it. Regtest only; not a Core
  option.
- **rbitcoin-cli gains `--named`, `--stdin`, `--rpcwait`, and
  `--getinfo`,** as in Core's client.
- **`getpeerinfo.last_block_announcement`**, as in Core.
- **Esplora `GET /block/:hash/txs/summary`.** One `[txid, fee, weight,
  value]` row per transaction, from stamped stats, so it is far cheaper
  than `getblock` verbosity 2 and still answers on a `--prune-seqsigwit`
  node. A dialect route, not in Blockstream's API.
- **Totals and full history above `--max-sh-creates` for a trusted local
  caller.** On the Esplora unix socket only, `GET
  /internal/address/:address` and `/internal/scripthash/:hash` return the
  totals, and `.../history` streams every confirmed transaction as
  Electrum `get_history` rows in 4,096-create waves. TCP Esplora and
  Electrum keep the cap.
- **Esplora serves blocks disconnected during this run**, with
  `in_best_chain: false`. A restart forgets them.
- **Silent Payments subscriptions follow the Frigate spec.** Sparrow
  wallets restore their history: a Unix-time `start` resolves to a height,
  the scan runs from where the client asked (not the last 256 blocks) in
  the background with `progress` notifications, and `"FROM-TO"` ranges
  work. A connection keeps up to 16 addresses
  (`--electrum-max-sp-subs`); the node runs at most 32 history scans at
  once.
- **Nightly container image.** The master tip is published nightly as
  `nightly` and `nightly-YYYYMMDD` for `linux/amd64` and `linux/arm64`,
  after a regtest boot of each arch.
