Added
- **`--network testnet5`** (BIP 95). Genesis mined at mainnet height
  975,744, pow limit `0x1a0fffff`, no 20-minute
  minimum-difficulty rule, message start `FIVE`, P2P port 18353, RPC port
  18352, `tb` addresses. Conf takes `testnet5` or `testnet5=1`; NixOS
  `services.rbitcoin.network = "testnet5"`. There are no seeds yet, so name
  a peer with `--connect`.
- **BIP 54 (consensus cleanup) on testnet5 from block 1.** Timewarp and
  negative-interval headers, witness-stripped 64-byte transactions, a
  coinbase not timelocked to the previous height, and more than 2,500
  legacy sigops in one transaction's inputs are invalid. The mempool
  refuses the 64-byte and over-2,500-sigop transactions; the header and
  coinbase rules are block-only. `getblocktemplate` lists
  `!consensuscleanup` and requires the client to name it, and SV2
  `NewTemplate` hands out the coinbase fields for a conforming coinbase.
  Official BIP 54 vectors run in the consensus suite. Other networks are
  unchanged.
- **Version 3 (TRUC) and anchor packages, as in Core.** RPC submit takes
  `nVersion` 1 to 3. A version-3 transaction follows BIP 431: one
  unconfirmed parent and one unconfirmed child, at most 10,000 vB (1,000 vB
  with an unconfirmed parent). A second child that pays enough evicts the
  first under Core's replacement rules instead of failing
  `TRUC-violation`. A 0-fee transaction may carry one 0-value anchor
  output, which its child must spend (`missing-ephemeral-spends`).
  `submitpackage` admits the anchor parent with its fee-paying child, and
  peers relay the pair as 1p1c, so Bark's exit packages reach the network.
- **A v1 P2P listener for local wallet indexers.**
  `--net-permission-bind v1,noban@127.0.0.1:8335` (conf
  `net_permission_bind=`) accepts plain v1 P2P for NBXplorer, bitcoinj and
  similar clients; a BIP324 peer there still gets v2. Every other listener
  and every outbound connection stay v2 only. The bind needs its own port
  and a private address (loopback intended), is never advertised, and
  stays up under `--listen=0`. `getpeerinfo.transport_protocol_type` is per
  peer.
- **`--rpc-client-version N`** (conf `rpc_client_version=`, NixOS
  `rpc.clientVersion`) sets `getnetworkinfo.version`. The default stays
  190000. Bark's captaind needs 310000.
- **`--discover-from-peers`**, off by default: with no clearnet
  `--external-ip` and a non-loopback P2P bind, announce the IP outbound
  clearnet peers say they
  reached us at, as Core's `-discover` does behind NAT. Never over Tor,
  I2P, CJDNS, or `--proxy`.
- **Regtest can retarget like mainnet.** `--regtest-block-time` and
  `--regtest-retarget-interval` (e.g. `10` and `60`) run mainnet's
  difficulty adjustment with Core's clamp, so a dev stack can exercise a
  difficulty change on a CPU. Validation, `generate*`,
  `getblocktemplate`, and SV2 all follow it. Regtest only; not a Core
  option.
- **rbitcoin-cli gains `--named`, `--stdin`, `--rpcwait`, and
  `--getinfo`,** as in Core's client.
- **`getpeerinfo.last_block_announcement`**, as in Core.
- **Esplora `GET /block/:hash/txs/summary`.** One `[txid, fee, weight,
  value]` row per transaction, from stamped stats, so it is far cheaper
  than `getblock` verbosity 2 and still answers on a `--prune-seqsigwit`
  node. A dialect route, not in Blockstream's API.
- **Totals and full history above `--max-sh-creates` for a trusted local
  caller.** On the Esplora unix socket only, `GET
  /internal/address/:address` and `/internal/scripthash/:hash` return the
  totals, and `.../history` streams every confirmed transaction as
  Electrum `get_history` rows in 4,096-create waves. TCP Esplora and
  Electrum keep the cap.
- **Esplora serves blocks disconnected during this run**, with
  `in_best_chain: false`. A restart forgets them.
- **Silent Payments subscriptions follow the Frigate spec.** Sparrow
  wallets restore their history: a Unix-time `start` resolves to a height,
  the scan runs from where the client asked (not the last 256 blocks) in
  the background with `progress` notifications, and `"FROM-TO"` ranges
  work. A connection keeps up to 16 addresses
  (`--electrum-max-sp-subs`); the node runs at most 32 history scans at
  once.
- **Nightly container image.** The master tip is published nightly as
  `nightly` and `nightly-YYYYMMDD` for `linux/amd64` and `linux/arm64`,
  after a regtest boot of each arch.
- **`rbitcoin-cli --rpcclienttimeout` and `--rpcwaittimeout`.** Both take
  seconds, and `0` means no limit, as in Core. `--rpcclienttimeout`
  applies to TCP and the unix socket. It defaults to Core's 900 seconds
  on TCP, up from the fixed 30 seconds, and to no limit on the unix
  socket as before. It also bounds the connect and the host name
  lookup, as does what is left of `--rpcwait`. A timeout names the
  option that ran out. A negative value is refused; Core reads it as no
  limit.
  `--rpcwaittimeout` caps how long `--rpcwait` retries and still defaults
  to 30 seconds (Core waits forever) (#1705).
- **`rbitcoin-cli` takes Core's single dash for every option.**
  `-rpcwait`, `-named`, `-stdin`, `-getinfo`, `-datadir=PATH`,
  `-rpcclienttimeout=0` and the rest parse as their `--` form, so
  `rbitcoin-cli -rpcclienttimeout=0 importmempool PATH` runs as written.
  `-h`, `-V` and a negative number parameter are unchanged, and a Core
  option the client lacks is still an unknown argument. A switch given a
  value (`--rpcwait=1`) is refused.
- **`ibd: perf_full` meters the IBD heap that `accounted` leaves out.** Each
  full line has an `owned.heap` object: the in-flight pin estimate the
  retain governor charges (`pin_est`) and the heap its maps hold at their
  high-water capacity past that estimate (`pin_maps`), the decoded bodies
  alive in the confirm pipeline (`decoded_blocks`, `decoded`), the spend
  delta's notes and page directory (`spend_notes`, `spend_dir`), and the
  confirm header plans (`conf_plans`). `work.map_bytes` is the work-path
  maps' heap from their capacity. These are meters only; `accounted` and the
  retain governor do not change. `docs/ibd-memory.md` has a `jq` line for
  the anonymous heap no meter names. The 5 s compact `ibd: perf` line still
  prints only its RSS summary.
- **CI runs the workspace test suite on macOS.** The new `macos-test` job
  runs `cargo test --workspace --exclude rbitcoin-bench --features skip-flushes`
  on `macos-26`. Until now, macOS CI ran only the smoke test. The job is not a
  required check yet.
- **Esplora `GET /mempool/removed` says why a transaction left the mempool.**
  A dialect route on both Esplora listeners lists the recent committed
  removals, oldest first, each with its sequence, txid, and Core's reason
  (`expiry`, `sizelimit`, `reorg`, `block`, `conflict`, or `replaced` with
  the replacing txid). To make the rows usable, `getrawmempool false true`
  now returns Core's `mempool_sequence`: it advances on every add and every
  removal, a mined block included, and is read with the txid list. A client
  that lists the pool at S1 and at S2 finds the reason for each txid that
  left in the row numbered `S1 <= seq < S2`.
- **Overlay journeys for daemon restarts.** The overlay-functional harness now restarts tor, i2pd and cjdroute under a running node and checks the node is reachable again at the same address without a restart: `tor_onion_comes_back_after_tor_restarts`, `i2p_destination_comes_back_after_i2pd_restarts` and `cjdns_listener_works_after_cjdroute_restarts`.
- **`--test bip94` enforces BIP94 on regtest.** It matches Core's
  `-test=bip94` (conf `test=bip94`): a difficulty period's first block
  more than 600 seconds before its parent is `time-timewarp-attack`, and
  a retarget starts from the period's first `nBits`. Another network or
  another option fails start. The Core-functional `bitcoind` shim
  forwards `-test=bip94` (#1779).
- **`logging` RPC.** Read or change debug categories at runtime, as in
  Core: `logging` lists each category, `logging '["mempool"]'` turns one
  on, `logging '[]' '["mempool"]'` turns it off. `"all"` covers every
  category, and an unknown name is refused without changing anything.
  The categories are rbitcoin's own log prefixes (`api`, `electrum`,
  `i2p`, `ibd`, `mempool`, `node`, `p2p`, `query`, `store`, `sv2`, `tip`,
  `tor`, `txrelay`). `--log-level debug` and `trace` start with all of
  them on, so startup output is unchanged.
- **Test suites can skip file flushes.**
  `cargo test --workspace --features skip-flushes` turns off every
  `sync_all` / `sync_data` in the `suite` target of the query, net, rpc,
  ibd, rbitcoin-test, electrum, esplora, sv2, and node crates. On macOS
  each flush waits on the whole drive, and those suites
  timed out. A node still flushes, and so do a node process a test starts
  and the crates' other test binaries.
